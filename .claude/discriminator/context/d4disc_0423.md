## 1. Executive summary

**D⁴-Disc** is implemented as:

- a **single conditional latent dynamics predictor** `f_θ(· | c)` with condition
  `c in {+, -, null}`,
- a **bootstrap loop** that updates a per-sample **routing probability**
  `gamma_j in (0, 1)` for dirty fail transitions, and
- a **CFG-style inference score** using the same \(ω\) knob as D³-Disc,
  computed from **residuals** against cached “target” latent vectors.

In code terms:

- **Training entry**: `robosuite.discriminator.d4disc.train_d4`
- **Model**: `models/dynamics.py::ConditionalDynamicsPredictor`
- **Two-phase trainer**: `training/trainer.py::D4Trainer`
- **Advantage gate**: `training/filter.py::compute_advantage_gate`
- **Inference**:
  - feature assembly from cache: `inference/feature.py::D4FeatureExtractor`
  - scoring + conformal calibration: `inference/detector.py::D4Detector`
  - benchmark adapter: `inference/benchmark.py::D4BenchmarkDiscriminator`

The design “bridge” remains the same as in `d4_disc_design.md`:
under a Gaussian residual model, **residual differences are log-likelihood
differences**, and thus an “advantage” computed from residuals provides a
principled separator for routing fail data and for guidance at inference.

## 2. Data and cache contract

### 2.1 Three populations of transitions (code)

The dataset class is `data/dataset.py::LatentFlowDynamicsDatasetD4` and scans
HDF5 rollouts (`expert/`, `success_rollout/`, `fail_rollout/`) but *only keeps*
transitions that have a corresponding cached `.npz` entry.

Each transition sample `__getitem__` returns:

- `current_image`: `(3, H, W)` 8-bit image tensor from cache
- `target_image`: `(3, H, W)` (horizon-shifted)
- `current_proprio`, `target_proprio`: 1D float vectors (possibly sliced/padded)
- `action_sequence`: `(horizon, action_dim)` float tensor (padded by repetition)
- `is_fail_raw`: bool
- `gamma`: scalar float copied from a dataset-owned **γ-buffer**
- `sample_idx`: the global index used to update γ later

The three populations correspond to:

- `D_pos`: `expert/` and `success_rollout/` (both `is_fail_raw=False`)
- `D_fail_raw`: `fail_rollout/` (`is_fail_raw=True`)
- `D_hold ⊂ D_pos`: a held-out slice used to monitor `r_plus` and clamp `alpha`
  (trainer-side, not detector conformal).

### 2.2 Cache reader invariant (legacy LPB cache)

`data/cache.py::PreprocessedCacheReader` implements a *legacy-compatible* cache
contract:

- cached file: `.npz` with arrays
  - `images_chw`: `(T, V, 3, H, W)` (V cameras, legacy naming)
  - `proprio`: `(T, P)`
  - `actions`: `(T, A)`
- cache key includes:
  - cache version token (`lpb_score_preprocessed_v2`)
  - image size, camera names list, proprio mean/std SHA1 tokens
  - `(task, file_path, demo_key, file_mtime)`

The cache reader selects `camera_index` (default 0) and returns a `PreprocessedDemo`
with `images_chw` shaped `(T, 3, H, W)` for a single camera stream.

**Practical implication**: training/inference are deterministic w.r.t. the HDF5
file path and `mtime`; touching the HDF5 file will change the cache key.

## 3. Model: ConditionalDynamicsPredictor (AdaLN-Zero)

### 3.1 Inputs / outputs (code contract)

`models/dynamics.py::ConditionalDynamicsPredictor` is a token-sequence model with:

Inputs:
- `obs_token`: `z_t` latent vector, shape `(B, latent_dim)`
- `proprio_token`: `s_t` proprio, shape `(B, proprio_dim)`
- `action_tokens`: action chunk `a[t:t+h]`, shape `(B, H, action_dim)`
- `cond_idx`: condition id, shape `(B,)` long, values in `{0,1,2}` for `{+, -, null}`

Outputs:
- `pred_latent`: `z_hat[t+h]` (optionally residual), shape `(B, latent_dim)`
- `pred_proprio`: `s_hat[t+h]`, shape `(B, proprio_dim)`

The sequence layout is:
```
x = [obs, prop, act_1, ..., act_H, pred_z, pred_s]   # shape (B, L, D)
```
with learned positional embeddings and a causal mask.

### 3.2 Conditioning mechanism: AdaLN-Zero per block (implemented)

Each transformer block is `models/adaln.py::AdaLNDecoderBlock`:

- `cond_idx` → `ConditionEmbedder(d_condition)` → `condition_vec` in R^(B, d_condition)
- each block produces `(shift, scale, gate)` for attention and MLP sub-blocks:
  - normalized tokens are modulated by `shift/scale`
  - residual contribution is multiplied by `gate`

The “AdaLN-Zero” property is achieved by **zero-initializing the modulation head**
weights when `adaln_init_std == 0.0`. In that case, for all conditions `c`,
the block starts as (approximately) identity at step 0, which keeps warm-up stable.

The code also supports `adaln_init_std > 0` to break symmetry early by injecting
small Gaussian noise into modulation heads (see `models/adaln.py::AdaLNModulation`).

### 3.3 Residual latent head (implemented; important for stability)

`ConditionalDynamicsPredictor(residual_latent_head=True)` uses:
```
z_hat[t+h] = z_t + Delta_theta(...)
```
and **zero-initializes** the latent head, so the model starts as identity on \(z\).
This was introduced to avoid the failure mode “trained predictor worse than identity”.

## 4. Training: two-phase state machine

Training is implemented in `training/trainer.py::D4Trainer`.

### 4.1 Phase A (warm-up; implemented)

For `warm_up_epochs` epochs, the trainer:

- trains on a loader that prioritizes clean positives
  (`_train_loader_phase_a` excludes `is_fail_raw=True` when possible),
- **forces condition to `c=+` for all samples** (`_sample_condition(..., phase="A")`),
- optimizes latent and proprio MSE against encoder-computed targets:
  ```
  L = w_z * || z_hat[t+h] - z_target ||^2 + w_s * || s_hat[t+h] - s_target ||^2
  ```
- maintains an EMA of predictor weights (`training/ema.py::ModelEMA`).

**Note (design-only vs code)**: the design doc discusses label dropout to train
the unconditional `null` branch during warm-up. The current code *does not*
drop to `null` in Phase A; it trains only `c=+` for stability/simplicity.

At the end of Phase A, the trainer computes a held-out distribution of
`r_plus := || z_hat_plus[t+h] - z_target ||^2` and sets
`schedule.alpha0 = 1 / MAD(r_plus)` (robust scale).

### 4.2 Phase A → Phase B warm-start (implemented, optional)

If `f3_warm_start=True`, the trainer initializes γ for fail samples using
`training/filter.py::warm_start_gamma_from_knn`:

- compute KNN squared distance `d2(j, D_pos)` in latent space
  (encoder features of cached images),
- map \(d^2\) to γ using either:
  - **rank** mode: normalized rank in \([0,1]\), or
  - **sigmoid** mode: `sigmoid(beta * (d2 - kappa))`.

This breaks the symmetric fixed point where `f(+) ~ f(-) => gamma ~ 0.5`.

If `f3_warm_start=False`, γ remains at 0.5 for all fail samples (higher risk).

### 4.3 Phase B (bootstrap; implemented)

For `bootstrap_epochs` epochs, each outer epoch does:

1. **(Gate update) with EMA weights**:
   - compute `r_plus` and `r_minus` on **fail transitions only**,
   - compute advantage
     ```
     A = (r_minus - r_plus) / (2 * sigma_sq)
     ```
   - update γ by a sigmoid gate:
     ```
     gamma_new = sigmoid(alpha_k * (-A - kappa_k))
     ```
   - apply an EMA smoother to γ in the dataset buffer:
     ```
     gamma = clip(alpha_ema * gamma_old + (1 - alpha_ema) * gamma_new)
     ```
     where `ema_alpha` is `cfg.ema_alpha_gamma` and the clip epsilon is `gamma_clamp`.

   If `gate_freeze_epochs > 0`, the advantage gate can be frozen for the first
   few bootstrap epochs (when warm-start is enabled) to prevent immediately
   collapsing back toward γ≈0.5.

2. **(Critic update) weighted routing via condition sampling**:
   training uses `D4Trainer._sample_condition(..., phase="B")`:
   - clean positives: `c=+` with probability \(1-p_{drop}\), else `c=null`
   - dirty fail:
     - with prob \(p_{drop}\): `c=null`
     - else: `c=+` with prob \(1-\gamma\), `c=-` with prob \(\gamma\)

   Then `_enforce_batch_balance` promotes some fail samples to `c=-` to ensure
   a minimum fraction `min_batch_balance` of minus conditions per batch.

3. **(Monitoring)**:
   after training, the trainer evaluates held-out `r_plus` and a “conditional delta”
   `E[||f(+) - f(-)||^2]` on a cached probe batch and may trigger rollback.

## 5. Advantage gate and γ-buffer dynamics

### 5.1 Gate computation (exactly as in code)

The gate update is implemented in `training/filter.py::compute_advantage_gate`.

For each fail transition \(j\) (iterated in batches over the fail subset):

- encode cached images to latent vectors with `Encoder`:
  \(z_t = Enc(x_t)\), \(z_{t+h} = Enc(x_{t+h})\)
- run the predictor twice:
  ```
  z_hat_plus  = f(z_t, s_t, a_chunk | c=+)
  z_hat_minus = f(z_t, s_t, a_chunk | c=-)
  ```
- compute latent residuals:
  ```
  r_plus  = ||z_hat_plus  - z_target||^2
  r_minus = ||z_hat_minus - z_target||^2
  ```
- compute advantage and γ update:
  ```
  A = (r_minus - r_plus) / (2 * sigma_sq)
  gamma_new = sigmoid(alpha_k * (-A - kappa_k))
  ```

Finally, the dataset γ-buffer is updated at the corresponding `sample_idx`:
```
gamma = clip(alpha_ema * gamma_old + (1 - alpha_ema) * gamma_new)
```
with `alpha_ema = cfg.ema_alpha_gamma` and clip eps `cfg.gamma_clamp`.

Returned diagnostics include γ quantiles and the mean “separation gap”
`E[r_minus - r_plus]` over fail transitions.

### 5.2 Why γ lives in the dataset (implementation choice)

The γ-buffer is stored in `LatentFlowDynamicsDatasetD4.gamma_buffer`, which makes:

- γ **index-stable** across data loader shuffles (updated by `sample_idx`)
- γ **saved** in checkpoints (`D4Trainer.build_payload`)
- condition sampling in training **stateless** (batch carries `gamma` scalars)

Conceptually, γ is the evolving dichotomous “label-policy” over dirty fail data.

## 6. Schedules (α, κ, η) and coupling

Schedule logic is `training/schedule.py::D4Schedule`.

### 6.1 α schedule and the C4 coupling proxy (implemented)

Raw schedule:
```
alpha_raw(k) = alpha0 * (1 + k) ** alpha_exponent
```

The design doc’s coupling condition (C4) \(\alpha_k\rho_k = O(1)\) is enforced
in code by clamping α using held-out `r_plus` as an error proxy:
```
alpha_k = min(alpha_raw(k), alpha_cap_rate / max(held_out_r_plus, eps))
```

Operationally: this prevents **early commitment** when the critic is noisy.

### 6.2 κ schedule (implemented; currently pinned)

`kappa(k)` returns `kappa0` and defaults to 0.0. This matches the design
recommendation for bootstrap (\(\kappa=0\)).

### 6.3 η schedule (present; not yet wired into the loss)

`eta(k)` ramps linearly from `eta0` to `eta_final` over `eta_ramp_epochs`.

However, the current `_run_step` loss is unweighted MSE (latent + proprio) and
does not explicitly include an η-weighted pseudo-positive reuse term. The trainer
still logs `eta_used` for visibility and future alignment.

## 7. Stability monitors and rollback behavior

### 7.1 Health signals (implemented)

Each bootstrap outer epoch records a `D4Health` tuple:

- `held_out_r_plus` (EMA model)
- `mean_gamma`, `separation_gap` (from the gate)
- `conditional_delta` (probe batch; EMA model)
- `alpha_used`, `kappa_used`, `eta_used`

### 7.2 CollapseDetector triggers (implemented)

`training/monitor.py::CollapseDetector` triggers rollback on:

- **early commitment**: mean γ ≤ 0.02 or ≥ 0.98 for `patience` consecutive checks
- **conditional collapse**: `conditional_delta < 1e-4` for `patience+2` checks
- **critic divergence**: held-out `r_plus` monotonically increases for 4 checks
- **branch starvation**: `separation_gap < 0` for 2 checks

Rollback action (trainer):

- apply EMA weights to the predictor
- halve `schedule.alpha0`
- reset detector counters

This is the “guardrail” layer that keeps the bootstrap loop from becoming
self-reinforcing in the wrong direction.

## 8. Inference: detector score, CFG, and conformal τ

Inference is implemented in `inference/detector.py::D4Detector`, with features
assembled by `inference/feature.py::D4FeatureExtractor`.

### 8.1 Feature assembly (implemented)

Given a cached trajectory `(task, file_path, demo_key)`:

- encode per-step cached images to latent vectors `z_t`
- set targets \(z_{t+h}\) by horizon shift (clamped at end)
- build action chunks \(a_{t:t+h}\) by padding with the last action
- slice/pad proprio to match `proprio_dim`

These are packaged as `D4Frames`:
`(z_current, z_target, proprio, action_chunks, length)`.

### 8.2 CFG-guided residual score (implemented)

For each step:
```
f_omega = (1 + omega) * f_plus - omega * f_minus
lambda_t = ||f_omega - z_target||^2 / (2 * sigma_sq)
```

Implementation notes:
- `omega` is clamped to \([0,2]\) for numerical stability.
- the detector also returns arrays `r_plus`, `r_minus`, and `advantage`
  for visualization/debugging.

### 8.3 Aggregation and conformal τ (implemented)

Per-step \(\lambda_t\) is aggregated via D³ helper `_aggregate_lambda`
(`lambda_mode` ∈ {mean,max}, optional window).

Calibration:
```
tau = percentile_delta({ aggregated_lambda(success_calibration) })
```
computed by `D4Detector.calibrate`.

The benchmark wrapper handles calibration splitting (optionally per-task).

## 9. Checkpoint payload contract

The trainer saves a single `.pt` payload containing:

- predictor: `raw_state_dict`, `ema_state_dict`, `arch_args`
- encoder: `encoder_state_dict`, `encoder_config`
- training state: `config`, `schedule_state`, `history`, `health_history`
- dataset state: `gamma_buffer`, `is_fail_raw`
- scoring scale: `sigma_sq`

Inference/benchmark loads **EMA weights** by default.

## 10. What differs from `d4_disc_design.md`

This section is intentionally explicit to prevent “theory drift”.

### 10.1 Conditional dropout in Phase A

- **Design doc**: suggests unconditional (`null`) branch training via dropout throughout.
- **Current code**: Phase A always uses `c=+` (no dropout). The `null` branch is
  exercised in Phase B via `p_cond_drop`.

### 10.2 η objective term is not yet wired

The design doc’s joint objective includes an η-weighted reuse term. The current
trainer schedules/logs η but does not apply it to the loss.

### 10.3 κ is pinned to 0

Design and code align on κ being effectively 0 during bootstrap; code keeps κ as
a hook for future variants.

### 10.4 Score form

The design doc discusses log-density combinations; the code uses the residual form
\(\lambda_t = \|f_\omega - z_{t+h}\|^2/(2\sigma^2)\), which is stable and reuse-friendly.
